# Handoff: magicdoor-pr-regression-handoff + pr-uat-cases Skill 重构

## Session Context

用户要求优化 `magicdoor-pr-regression-handoff` skill 的 description，并表示希望继续一起优化该 skill 及 sibling skill `magicdoor-pr-uat-cases`。使用 `grill-me` skill 进行了深度 interview，加载了 `superpowers:writing-skills` 作为最佳实践参考。

## 已确定的设计决策

### 1. Description 最终版

```yaml
description: >-
  Use when a feature branch is ready for creating a new PR or updating an
  existing PR with regression documentation for QA handoff.
```

**决策依据：**
- 以 "Use when..." 开头（writing-skills CSO 铁律）
- 明确区分 new/existing PR（帮助 Claude 在两种场景下都能识别到 skill）
- "regression documentation" 而非 "regression test documentation"（避免与生成测试用例的 sibling skill 混淆）
- 项目限定（MagicDoor）从 description 移除，放到 SKILL.md content 中
- 不包含 "push" 关键词（用户选择不含 push 版本）

### 2. Architecture 重大变更

| 变更项 | 旧设计 | 新设计 |
|--------|--------|--------|
| Marker | `REGRESSION_DOC_HERE` | `UAT_CASES_HERE` |
| Regression doc 文件 | 生成 `{feature-slug}-regression.md`，PR body 里插链接 | **取消 regression doc 文件**，UAT cases 内容直接嵌入 PR body |
| UAT cases 输出位置 | `.knowledge/notes/plans/YYYY-MM-DD-must-test-uat-cases.md` | `.tmp/uat-cases.md`（repo 内，被 .gitignore，不 tracked） |
| Skill 关系 | 各自独立，无明确调用关系 | `pr-uat-cases` 独立运行生成临时文件，`pr-regression-handoff` 读取并嵌入 PR body |

**UAT cases 嵌入流程：**
1. `pr-uat-cases` 运行 → 生成 `.tmp/uat-cases.md`（覆盖旧文件）
2. `pr-regression-handoff` 运行 → 读取 `.tmp/uat-cases.md` → 把内容复制到 PR body 的 `UAT_CASES_HERE` marker 处
3. 临时文件读取后**保留**（供用户手动查看），固定路径 `.tmp/uat-cases.md`
4. 如果 `.tmp/uat-cases.md` 不存在 → STOP 并提示用户先运行 `pr-uat-cases`

### 3. Base Branch 统一检测

**旧设计：** 所有 workflow hardcode `origin/master`
```bash
git fetch origin master
git rebase origin/master
git log origin/master..HEAD --oneline
```

**新设计：** 复用 `pr-uat-cases` 的 base branch 检测逻辑
```bash
git remote show origin | grep "HEAD branch"
```
- 在 `SKILL.md` 前置步骤中统一检测，记录为变量
- 所有 workflow 引用检测到的 base branch（`origin/main` 或 `origin/master`）
- 避免 `master`/`main` 不一致导致的 rebase/diff 失败

### 4. Skill 边界划分

| Skill | 职责 |
|-------|------|
| `pr-regression-handoff` | PR 流程 orchestration：base branch 检测、rebase、pre-push checks、push、PR 创建/更新、PR body 组装（含 UAT cases 嵌入） |
| `pr-uat-cases` | UAT cases 内容生成：diff 分析、base branch 验证、测试用例生成、输出到 `.tmp/uat-cases.md` |

## 待解决/待确认的问题

### Question 10（用户尚未回答）

**`pr-uat-cases` 输出格式与 PR body 嵌入的兼容性**

当前 `pr-uat-cases` 输出包含 h1 标题 (`# Must-Test UAT Cases...`) 和 metadata block，直接嵌入 PR body 会导致 Markdown 嵌套 h1 问题。

提出的方案：
- **(A) 双文件模式**：`.tmp/uat-cases.md`（完整版，带标题）+ `.tmp/uat-cases-embed.md`（精简版，只 cases，用于嵌入）
- **(B) `pr-regression-handoff` 智能过滤**：读取后去掉标题/metadata，保留 cases
- **(C) 调整 PR template 结构**：`UAT_CASES_HERE` 放在 `## UAT Test Cases` section 内
- **(D) Frontmatter 分隔**：用 YAML frontmatter 包装 metadata

**推荐 (A) 双文件模式**，但需用户确认。

### 后续待 grill/待解决的问题

1. **Update mode 重建 PR body 的风险**：当前 `update-pr.md` 第 134 行 "Replace the existing PR body entirely... Do not preserve old content." 会导致手动编辑内容丢失。是否需要改为增量更新（只替换 `UAT_CASES_HERE` 部分）？
2. **Pre-push checks**：`pre-push.md` 的 project type 检测（`package.json` > `go.mod` > ...）在 Rush monorepo 中可能检测错误（多个 package.json）。是否需要调用 `rush-monorepo` skill 或增加 Rush 检测？
3. **Auto-commit 未提交变更**：`SKILL.md` 要求 "stage all changes and commit with an LLM-generated message"，这是否安全？是否应该让用户确认 commit message？
4. **实际 skill 文件重构实施**：所有已确定的设计变更需要写入实际 skill 文件（SKILL.md + workflows/）
